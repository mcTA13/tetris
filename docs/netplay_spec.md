# ネット対戦 仕様書

ネット越しに人と人が 1 対 1 で対戦できるようにするための仕様。まだ実装していない。

## 1. 範囲

- 対象: 人どうしの 1 対 1 の対戦（CPU 対戦と同じルール）
- 対象外: 3 人以上の対戦、観戦、ランキング、ずる対策

## 2. 基本方針

**自分の盤面は自分の PC が計算し、相手には「盤面の様子」と「攻撃」だけを送る。**

- ロックステップやロールバック（両方の PC で両方の盤面を計算する方式）は採らない
- 理由: テトリスの対戦で相手の盤面に影響するのはおじゃま（攻撃）だけ。攻撃が通信の分だけ（0.1 秒程度）遅れて届いても遊びに影響しない
- 自分の操作は自分の PC の中だけで完結するので、ネット越しでも操作感は 1 人用と同じ
- 相手の盤面は、届いた様子をそのまま描くだけ（自分の PC では相手の盤面を計算しない）

## 3. 接続方式

| 段階 | 方式 | 内容 |
|---|---|---|
| 1 | IP 直接接続（Godot の ENet、UDP） | ホストが待ち受け、参加者がホストの IP アドレスとポートを入力してつなぐ。インターネット越しではホスト側のポート開放が必要 |
| 2 | WebRTC ＋ 仲介サーバー | ルームコード（英大文字 4 文字）を伝えるだけでつながる。仲介サーバーは接続情報の受け渡しだけを行い、試合中の通信は PC どうしで直接行う |

- 段階 1 で動きを固め、そのあと段階 2 を追加する。送るメッセージの中身は両方で同じ
- 既定のポート: 47240（設定で変更可）
- 段階 2 の仲介サーバーは小さな無料枠（Cloudflare Workers など）で動く規模にする。STUN は公開サーバーを使う。TURN（中継）は使わない（つながらない回線では段階 1 を案内する）

## 4. 役割

- **ホスト**: 部屋を作る側。試合のルールを決め、開始の合図を出し、同時に負けたときの判定をする
- **ゲスト**: 部屋に参加する側
- 盤面の計算については両者対等（どちらも自分の盤面だけを担当）

## 5. 試合のルール

- ホストが決めて、開始前に `rules` で送る。対戦中は両者が同じ値を使う

| 項目 | 内容 |
|---|---|
| 先取本数 | 1〜3 本 |
| ライン消去の待ち時間 | 18F 固定 |
| 出現の待ち時間（ARE） | 0F 固定 |
| マージンタイム | 1 分ごとに落下速度が 1 段上がる（CPU 対戦と同じ） |
| 攻撃量 | ガイドライン準拠（CPU 対戦と同じ） |
| ミノの順番 | ラウンドごとにホストが種（seed）を決め、両者同じ順番 |

- DAS・ARR・ソフトドロップ速度・ボタン割り当て・テーマ・言語は各自の設定のまま（相手に影響しないため）

## 6. 流れ

1. タイトル → 対戦 → ネット対戦 → 「部屋を作る」または「部屋に入る」
2. 接続できたら、両者が `hello` を送り合う（バージョンが違えば切断して理由を表示）
3. ロビー画面: 相手の名前と通信の遅れ（ms）を表示。ホストがルールを決める
4. 両者が「準備OK」を押すと、ホストが `start` を送る
5. READY → GO の後に開始（開始の時刻は `start` を受け取ってから 1.5 秒後にそろえる）
6. ラウンドの決着 → 結果表示 → 次のラウンド（先取するまで）
7. 試合後: 「もう一戦」（両者が選ぶと同じルールで再開）または「ロビーへ」「タイトルへ」

## 7. メッセージ

- 形式: JSON。どのメッセージにも `type` を付ける
- 送り方は 2 種類
  - **確実**: 必ず届き、順番も守られる（ENet の reliable チャンネル）
  - **最新だけ**: 届かないことがあるが、新しいものが来れば古いものは不要（unreliable ordered チャンネル）

| type | 方向 | 送り方 | 中身 | いつ |
|---|---|---|---|---|
| `hello` | 両方 | 確実 | `version`（ゲームのバージョン）、`name`（表示名、最大 12 文字） | 接続直後 |
| `rules` | ホスト→ゲスト | 確実 | `first_to`、`line_clear_frames`、`are_frames` | ロビーで変更したとき |
| `ready` | 両方 | 確実 | `ready`（true / false） | 準備OK の切り替え |
| `start` | ホスト→ゲスト | 確実 | `round`、`seed` | ラウンド開始 |
| `state` | 両方 | 最新だけ | 下記 | 1 秒に 20 回 |
| `event` | 両方 | 確実 | `kind`（`clear` / `hard_drop` / `garbage_rise` など）と、ゲーム内イベントと同じ中身 | 起きたとき（相手の画面の演出用） |
| `attack` | 両方 | 確実 | `seq`（通し番号）、`lines` | 攻撃を送ったとき |
| `topped_out` | 両方 | 確実 | `round`、`tick`（ラウンド開始からのフレーム数） | 負けたとき |
| `round_result` | ホスト→ゲスト | 確実 | `round`、`winner`（`host` / `guest` / `draw`）、`wins` | 決着をホストが確定したとき |
| `rematch` | 両方 | 確実 | `want`（true / false） | 試合後 |
| `ping` / `pong` | 両方 | 最新だけ | `t`（送った時刻） | 1 秒に 1 回 |

### `state` の中身

| 項目 | 内容 |
|---|---|
| `tick` | ラウンド開始からのフレーム数（古い `state` を捨てるのに使う） |
| `board` | 盤面の見えている 22 行（見える 20 行＋上 2 行）。1 マス 1 文字（`.` 空き、`IOTSZJLG` ミノ）を連長圧縮した文字列 |
| `piece`、`rot`、`x`、`y` | 操作中のミノ（なければ `piece` は空） |
| `hold`、`hold_used` | ホールド |
| `next` | NEXT 5 個 |
| `incoming` | 予告ゲージの量 |
| `combo`、`b2b` | REN・B2B のカウンター表示用 |
| `clearing` | 消去待ちの行（消える演出用） |
| `stats` | 置いた数、送ったライン数（APM・PPS の表示用） |

通信量の目安: `state` 1 件あたり 100〜200 バイト × 1 秒 20 回で、1 秒あたり 4KB 程度。

## 8. 攻撃と相殺

- 攻撃した側: 今と同じく、ラインを消したら自分の予告をまず相殺し、余りを `attack` で送る
- 受け取った側: `attack` を受け取ったら自分の予告に積む（`GameState.receive()`）。穴の位置は受け取った側が決める
- 予告がせり上がるのは、受け取った側がラインを消さずにミノを置いたとき（今と同じ）
- 同じ `seq` を 2 回受け取ったら 2 回目は無視する（再送への備え）
- 攻撃の玉の演出は、`attack` を受け取った側で相手の盤面から自分の予告ゲージへ飛ばす

## 9. 勝敗の判定

- 自分が負けたら（ゲームオーバー）、すぐ `topped_out` を送り、自分の画面は「相手の結果待ち」にする
- ホストは両者の `topped_out` を見て決着を確定し、`round_result` を送る
  - 片方だけ負けた: もう片方の勝ち
  - 両方が負けを送ってきて、`tick` の差が 6 フレーム（0.1 秒）以内: 引き分け
  - 差がそれより大きい: 先に負けたほうの負け
- ホストは、最初の `topped_out` から 1 秒待ってから確定する（相手の `topped_out` が遅れて届く分を待つ）
- 勝ち数はホストのものを正とし、`round_result` の `wins` で両者をそろえる

## 10. 切断と遅れ

- `ping` が 3 秒届かなければ「通信待ち…」を表示する（ゲームは止めない）
- 10 秒届かなければ切断とみなす
  - 試合中: 残った側の勝ち（そのラウンドも試合も）。戦績には記録しない
  - ロビー: ロビーから出て、タイトルに戻る
- 遅れ（ping の往復時間の半分）は画面の端に ms で表示する。200ms を超えたら黄色、400ms を超えたら赤で表示する

## 11. ネット対戦だけの決まり

- ポーズはできない（Start ボタンは「降参する／続ける」の確認画面を出す。降参は負けとして `topped_out` を送る）
- リトライボタン（Back）は使えない
- 試合の戦績は「ネット対戦」として勝ち・負けを記録する（相手ごとには記録しない）

## 12. 画面

- **メニュー**: 対戦 → 「ネット対戦」を追加
- **接続画面**: 「部屋を作る」「部屋に入る」。部屋に入るときは IP アドレス（段階 1）またはルームコード（段階 2）を入力する。入力はコントローラーでもできるよう、文字を十字キーで選ぶソフトウェアキーボードを用意する
- **ロビー**: 自分と相手の名前、通信の遅れ、ルール（ホストだけ変更可）、準備OK の状態
- **対戦画面**: CPU 対戦と同じ配置。右側の名前に相手の名前、遅れの表示を追加
- **結果画面**: CPU 対戦と同じ。「もう一戦」「ロビーへ」「タイトルへ」

## 13. 作る部品

| 部品 | 役割 |
|---|---|
| `scripts/net/net_session.gd`（autoload） | 接続・切断、メッセージの送受信、`ping`。テスト用に、わざと遅れ・取りこぼしを起こす機能を持つ |
| `scripts/net/remote_field.gd` | 届いた `state` を、`FieldView` が描ける形（今の `GameState` と同じ項目）に組み立てる。`event` を受け取ったら演出のイベントを出す |
| `scripts/net/net_opponent.gd` | 対戦画面から見た「相手」。CPU 対戦の相手（`CpuPlayer` ＋ `GameState`）と差し替えられる形にする |
| `scripts/view/versus.gd` | 相手を「CPU」と「ネット」のどちらにも差し替えられるように整理する |
| `scenes/net_lobby.tscn` | 接続画面とロビー |
| 段階 2: 仲介サーバー | ルームコードと WebRTC の接続情報の受け渡しだけを行う小さなサーバー |

## 14. テスト

- **自動テスト**: 同じ PC の中で 2 つのゲームを通信させ、両方とも CPU を操作役にして最後まで戦わせる。決着が両者で一致すること、送った攻撃の合計と受け取った攻撃の合計が一致することを確かめる
- **悪条件のテスト**: `net_session` の機能で遅れ（100・300ms）、取りこぼし（5%）、一時的な切断を起こし、決着と攻撃の数がずれないことを確かめる
- **手動テスト**: 同じ PC で 2 つのウィンドウを起動して対戦する。次に LAN 内の 2 台で対戦する

## 15. 作る順番

1. 対戦画面の整理（相手を CPU とネットで差し替えられる形に）。今の CPU 対戦が壊れないことをテストで確かめる
2. IP 直接接続で、同じ PC の 2 つのウィンドウで対戦できるところまで
3. 遅れ・取りこぼし・切断への備えと、そのテスト
4. 接続画面・ロビー・メニュー
5. ルームコードでの接続（WebRTC ＋ 仲介サーバー）

## 16. 割り切り・リスク

- **ずる対策はしない**: 自分の盤面は自分の PC が決めるので、改造すれば攻撃量などをごまかせる。友達どうしで遊ぶ前提とする
- **バージョンの一致が必要**: `hello` で確かめ、違えば対戦しない
- **ルーター越しの接続**: 段階 1 ではポート開放が必要。気軽に遊ぶには段階 2 が必要
- **攻撃の届く遅れ**: 遅れの分だけおじゃまの到着が遅れる。300ms 程度までは遊びに影響しない想定
